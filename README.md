# Research Discovery Hub — Information Retrieval Assignment 2

This submission is a complete Streamlit-based Information Retrieval system for discovering research and technical material. Every activity required by the assignment—collection, preprocessing, index management, search, ranking, recommendation, evaluation, and analytics—is launched from the Streamlit front end.

## Quick start

Use Python 3.10 or later.

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Open the local address Streamlit prints. No separate backend command is required.

## Reproducible demonstration

1. Open **Acquire & Crawl** → **Demo dataset** → **Load or refresh demo corpus**.
2. Open **Index Management** and verify the inverted index snapshot.
3. In **Search & Ranking**, search for `ranking` and set PageRank influence to `0.20`. Set it to `0.00` to compare lexical BM25 alone.
4. In **Recommendations**, select a document and record a “Relevant / save” signal. Inspect the Top-K hybrid recommendations and their component scores.
5. In **Evaluation**, leave “Use supplied demo relevance judgments” selected and run at `K = 5`.
6. Capture the required BITS Lab screenshots: acquisition/dashboard, ranked search results, and evaluation comparison.

## Verification

Run the automated core regression suite before the Virtual Lab demonstration:

```bash
python -m unittest discover -s tests -v
```

The tests rebuild the 15-document corpus in an isolated in-memory database and cover index statistics, Boolean/phrase/negative queries, duplicate and URL validation, standard metric definitions, evaluation comparison, and feedback-aware recommendations.

The included corpus has 15 compact research documents, a reproducible citation graph, and 19 graded relevance judgments across five queries. It is intentionally small so that each component is explainable during a lab demo. Add web pages, Crossref results, or a CSV dataset through the UI for a larger experiment.

## Input formats

### Document CSV

Required columns:

```text
url,title,raw_text
```

Optional columns: `source`, `author`, `published`.

### Relevance judgments (qrels) CSV

```text
query,url,relevance
```

`relevance` is `0` for non-relevant and a positive grade for relevant. The URL must match the indexed document URL.

## Requirements coverage

| Assignment requirement | Implementation |
|---|---|
| Streamlit workflow | Dashboard, acquisition, index management, search/ranking, recommendations, evaluation, mining and analytics pages |
| Heterogeneous acquisition | CSV upload, Crossref public API, and multi-seed web crawler |
| Configurable crawling | Depth 0–2, page limit, multiple seed URLs, robots.txt check, polite delay |
| Duplicate control | Normalized URLs, SHA-256 normalized content hash, trigram-shingle Jaccard near-duplicate check |
| Metadata/content separation | SQLite fields separately store metadata, raw contents, clean contents, keywords and classification |
| Text mining | Tokenization, stop-word removal, optional stemming comparison, keyword extraction, rule-based document profile/classification and feature charts |
| Search | Boolean AND/OR/NOT, quoted phrases, inverted-index candidate filtering, BM25 scoring |
| Ranking | Iterative PageRank over stored crawl links; user-adjustable BM25/PageRank blend and explanation chart |
| Recommendation | Configurable Top-K TF-IDF cosine recommendations plus positive/negative feedback and a collaborative hybrid signal; visible component scores |
| Evaluation | Full-ranking Precision, Recall, F1, MAP and MRR plus Precision@K, Recall@K and NDCG@K; BM25 vs. BM25+PageRank comparison |

Runtime state is stored under `output/` when the app runs. It contains the SQLite collection and a downloadable `index_snapshot.json`; these are generated locally and are not needed for a fresh run.

## Deploy to Streamlit Community Cloud

The repository is already deployment-ready: the entry point (`app.py`), dependencies (`requirements.txt`), demo data, and optional theme configuration (`.streamlit/config.toml`) are all at the repository root.

1. Create a GitHub repository and push this project, excluding the generated `.venv/` and `output/` directory (the included `.gitignore` does this).
2. Sign in to [Streamlit Community Cloud](https://share.streamlit.io/) with GitHub, select **Create app**, then choose the repository, branch, and `app.py` as the entry point.
3. Choose Python 3.12 in Advanced settings, optionally choose an app subdomain, and deploy.
4. Test the deployed app by loading the demo corpus, then share the resulting `https://<your-app>.streamlit.app` link.

Community Cloud looks for `requirements.txt` at the entry point or repository root and installs it during deployment. The app does not require secrets. Its crawler rejects localhost/private network targets in addition to checking robots.txt; still, only crawl publicly permitted sites. See Streamlit’s official [deployment guide](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy) and [dependency guide](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies).

## Responsible crawling note

Only crawl sites where collection is permitted. The crawler checks `robots.txt`, identifies itself with an educational user agent, normalizes URL fragments, and applies a 0.35-second delay. Keep the depth and page limit small for lab demonstrations.
